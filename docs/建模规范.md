# 建模规范

## 坐标系与单位

- 右手系，**x 向东、z 向南（负值为北）、y 向上**，单位米。
- 原点取校园几何中心；布局范围约 x ∈ [-350, 350]，z ∈ [-450, 450]。
- 所有数值按 R1 总平面图目测归一化换算，**是布局级示意值，不是测绘坐标**。

## 数据文件 `data/layout.csv`

| 列 | 含义 |
|---|---|
| `name` | 元素名称（与 R1 图例 / R3 命名对齐） |
| `kind` | `building` / `road` / `water` / `green` / `plaza` / `field` / `terrain` |
| `x`, `z` | 平面中心坐标 |
| `w`, `d` | 东西向宽、南北向深 |
| `h` | 建筑为高度；面状元素为离地高度（用于叠放层次） |
| `color` | 十六进制颜色，如 `#c9c3b4` |
| `note` | 来源 / 状态备注（**不要写逗号**） |

名称含「广场」的元素按圆形生成，其余面状元素按矩形生成，建筑按长方体生成。

## 校准流程

1. 对照 `refs/official_01_plan_d.jpg` 或 `refs/official_05_pdf_embedded.jpg`，找出偏差元素。
2. 修改 `data/layout.csv` 中对应的 `x / z / w / d / h`。
3. 推送。云端 workflow 自动重新生成 `models/campus_layout.glb` 并更新 Pages。
4. 在预览首页并排对照 R1 底图与 3D 模型，继续迭代。

## 脚本

`scripts/build_layout.py` 只用 Python 标准库（csv / json / struct / math），生成 glTF 2.0 二进制 GLB：

- 每个元素一个 primitive，共享 buffer；材质按颜色去重
- 顶点属性 POSITION + NORMAL，索引 UNSIGNED_SHORT，4 字节对齐
- 同时输出 `models/layout_report.json`（元素数、三角面数、坐标范围）便于核对

云端运行：`python scripts/build_layout.py`。本地不运行建模任务。

## 精度分级（后续可升级）

| 级别 | 内容 | 当前 |
|---|---|---|
| 示意级 | 色块 + 少量体块 | — |
| 布局级 | 主要建筑体量、路网、绿化、水体、运动场、地形底板 | ✅ 当前 |
| 建筑级 | 立面、屋顶细节、材质贴图、单株树木 | 暂不做 |

## 合规

- 不使用境外地图服务、卫星影像、测绘成果坐标。
- 如需地图底图，只用腾讯地图 / 高德 / 百度 / 天地图，且不内嵌 API 密钥。
- 模型与预览页统一标注「教学展示用途 · 示意性布局 · 非测绘成果 · 不作导航或工程依据」。
- 不标注涉密或敏感设施，不公开精确地理坐标。
